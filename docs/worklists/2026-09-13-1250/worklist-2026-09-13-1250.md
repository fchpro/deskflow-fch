## Execution scope

- Direct streaming between already-connected computers on a reachable local network; no hosted service or internet relay.

- Either computer may send or receive regardless of its Deskflow keyboard/mouse server role.

- One source to one destination per session initially; document concurrency behavior explicitly.

- Include Windows and macOS in both directions. Include Linux X11/Wayland in the capability and validation matrix; any inability to deliver a required platform remains a blocker, not an implicit scope reduction.

- Browser source means a captured browser window. An isolated browser tab is a separate capability requiring explicit scope approval.

- App source means a selected window, not automatically all windows belonging to its process.

- Video-file source includes playback, pause/resume, seeking, end-of-file, and audio; supported formats must be listed and verified.

- Audio OFF must transmit no audio. Distinguish whole-system audio from application audio in the selector; do not silently substitute one for the other.

- Viewing only is the default. Interactive control needs explicit sender authorization and an immediate local way to revoke it.

- Screen/window mode controls the source computer when authorized. File mode controls media playback rather than injecting desktop input.

- Receiving a stream requires visible acceptance. Streaming is never started silently by reconnect or app launch.

- Protected media, minimized windows, secure desktops, OS permissions, and unavailable audio paths require explicit capability results; never present unsupported capture as successful streaming.

- No recording, microphone feature, multi-recipient broadcast, browser extension, or cloud account is implied by this plan.
