## Component and packaging decisions

Use **GStreamer 1.28.7** for media graphs, file decode, VP8/Opus encode/decode, RTP, WebRTC and audio sinks. Keep Qt Widgets for UI. Native capture adapters feed `appsrc` where the selected platform API is not directly exposed. No FFmpeg child process in the product, no custom unencrypted media socket, and no Qt Multimedia dependency.

- Video baseline: `vp8enc`/`vp8dec`, I420 SDR BT.709, `deadline=1`, no lookahead, explicit threads and bitrate. Software encoding is the selected baseline, not a fallback. Hardware H.264/AV1 can be a future explicitly negotiated option; it is not required to bootstrap implementation.
- Audio: `opusenc`/`opusdec`, 48 kHz stereo, 20 ms packets, 96 kbit/s; PCM conversion/resampling before encode. Audio OFF creates no audio source or RTP track and sends zero audio packets.
- Transport: `webrtcbin`, `rtpvp8pay/depay`, `rtpopuspay/depay`, DTLS-SRTP, libnice ICE; `rtpgccbwe` wired through the auxiliary sender callback and negotiated transport-wide congestion feedback. `webrtcbin` alone must not be claimed to provide configured congestion control.
- Core transport remains independent. No pixel/audio buffers or codec work enter the input event queue.
- Link via CMake imported pkg-config targets for `gstreamer-1.0`, `gstreamer-app-1.0`, `gstreamer-video-1.0`, `gstreamer-audio-1.0`, `gstreamer-webrtc-1.0`, `gstreamer-sdp-1.0`; require version >=1.28.7 and record actual resolved versions. Optional `BUILD_STREAMING` must be explicit; ON fails configuration if dependencies are missing, never silently disables the feature.
- Required plugin manifest: coreelements, app, playback/typefind, videoconvertscale, audioconvert/audioresample, vpx, opus, rtp/rtpmanager, webrtc, nice, dtls, srtp, sctp, rsrtp (GCC), matroska, isomp4, videoparsersbad, libav, plus platform capture/output plugins. Probe each actual factory/property at startup and report missing components as errors. Keep `wasapi2src continue-on-error=false`.
- Pin the official 1.28.7 distribution and its checksums; retain its plugin/dependency versions in a generated deployment manifest. Do not mix arbitrary system plugins with bundled plugins. Ship runtime libraries, plugin scanner, plugin directory and license notices. Set private plugin search paths for the packaged process; audit OpenSSL DLL collisions with existing vcpkg OpenSSL before packaging.
- GStreamer is LGPL; plugin/dependency licenses vary. Inventory shipped binary licenses (including libvpx, Opus, libnice, libsrtp, OpenSSL, FFmpeg/libav and Rust plugins); exclude unneeded GPL/ugly encoders. Existing application includes GPL-2.0-only with OpenSSL exception; no blanket redistribution/license-clearance claim is made. Packaging review belongs to item 11. [Licensing reference](https://gstreamer.freedesktop.org/documentation/frequently-asked-questions/licensing.html).

## Process, thread and integration ownership

Component paths:

| Path/component | Responsibility |
|---|---|
| `src/lib/streaming/` | implemented framing/session broker/TLS/private IPC/core service plus native capture/frame plumbing; VP8/Opus WebRTC transport/telemetry |
| `src/lib/gui/streaming/` | Stream dialog, explicit receiver acceptance, sender status, viewer, source selection and playback commands |
| `src/lib/net/SecureSocket.cpp` | accepted input exporter publication and synchronous binding revocation; Client/Server activate only after input handshake |
| `src/unittests/streaming/` | focused new tests; do not alter protected existing master tests |

- GUI process owns consent and media lifetime in the interactive user's session. Native source selection runs on the UI thread only when OS API requires it. GStreamer graphs, bus handling, encoding and signaling callbacks use a dedicated media worker with its own GLib context. Capture callbacks enqueue bounded buffers; queued Qt signals deliver status/latest frame. Rendering owns at most one pending frame and never blocks capture.
- Core owns authenticated connection identities and input arbitration. A separate signaling worker owns TCP/TLS reads, writes and parsers. Core event thread sees small typed lifecycle/control events only. Daemon must not capture a service/secure desktop.
- New private IPC is a separate per-login endpoint. Validate Windows named-pipe client PID/token/logon SID or Unix peer credentials against the interactive session. Restrict OS ACL/permissions. In service mode validate the active session SID rather than accepting every local user. Never convey grants/exporter material over the existing world-access endpoint. Reject unauthorized connection before parsing commands; no secret logging or replay queue.
- Private IPC/control frames: 32-bit network-endian length + bounded UTF-8 JSON, maximum 64 KiB (SDP/signaling envelope 256 KiB), incremental reads, bounded writes and schema/version validation. Repeated fields/unknown message types and invalid numeric ranges fail closed. Limit pending incoming offers to one per local endpoint.

## Secure discovery and session contracts (item 02)

Keep input protocol 1.8 unchanged. A streaming-capable core server exposes a **separate TCP 24801** signaling broker on the same configured interface. Streaming-capable clients probe only their already-connected server address after input authentication; one bounded probe per input connection. Old server/no listener means `peerUnsupported`, with ordinary input unaffected. Broker port is the configured input TCP port + 1 (24801 by default; input port 65535 disables streaming); no port scan or opportunistic endpoint substitution.

1. Require an active input connection at `PeerAuth` on both ends. Core exports 32 bytes with OpenSSL `SSL_export_keying_material`, label `EXPORTER-Deskflow-Streaming-v1`, context `1.8:` + the input client wire name. Protocol 1.8 does not carry a canonical server name; certificate hashes authenticate identities. Keep this binding in core memory only. [OpenSSL API](https://docs.openssl.org/master/man3/SSL_export_keying_material/).
2. Sidecar uses mutually pinned TLS 1.3 certificates matching that active input connection, then challenge/response HMAC-SHA256 using its exporter binding over both random nonces, both certificate hashes and the input connection generation. The implementation uses fresh challenge nonces inside mutually certificate-pinned TLS 1.3; Qt exposes no public sidecar-exporter API. Both TLS endpoints must possess the pinned private key, and both must prove the active input exporter. Ordered peer hashes prevent reflection; fresh nonces prevent replay. This supersedes the earlier sidecar-exporter requirement without permitting unpinned TLS or password/name-only authentication. Reject stale/disconnected bindings, downgrade, replay, or mismatch. The server can look up by fingerprint before accepting claimed names. Never promote a peer from a claimed name/IP alone.
3. Broker publishes a roster only of authenticated streaming peers with private GUI IPC attached. GUI gets immutable `PeerId` (certificate hash), canonical display name, connection generation and directional capabilities. Server can be either media sender or receiver; clients can stream directly to each other through brokered signaling. Broker relays signaling only and is the already-trusted authority for roster identities; it never relays media.
4. Messages: `Capabilities`, `Offer`, `Accept`, `Decline`, `SdpOffer`, `SdpAnswer`, `IceCandidate`, `Ready`, `PlaybackState`, `PlaybackCommand`, `ControlGeometry`, `ControlInput`, `GrantControl`, `RevokeControl`, `Stop`, `Stopped`, `Error`, `Heartbeat`. Envelopes carry version 1, random 128-bit session ID, sender/receiver PeerId, connection generation, sequence and source generation. Broker derives sender identity from authenticated channel, never forwarded claims.
5. Accepted offer binds source identity, audio scope, preset, viewing/control mode and WebRTC SDP DTLS SHA-256 fingerprint. Brokered authenticated signaling binds these to the intended peer before setting remote SDP. No media/capture starts before visible receiver Accept; no input before separate sender grant. Remote candidate values are validated and restricted to the selected peer's permitted direct LAN addresses; reject arbitrary third-party targets.
6. ICE is direct LAN UDP only, bounded local range **24802–24831**, BUNDLE/RTCP mux. No external STUN/TURN, cloud relay or TCP-media substitution. Set both libnice port range and candidate policy explicitly. Candidate failure gives an actionable connection error.
7. One session per host total (sending OR receiving). Busy rejects extra offers; no automatic preemption. Session states: `Idle -> Offering/AwaitingConsent -> Negotiating -> Starting -> Streaming/Paused -> Stopping -> Idle`; terminal error carries reason then cleans up. Consent expires after 30 s; transport negotiation 10 s; first frame 3 s after transport ready; heartbeat every 1 s with 3 s timeout. OS dialogs may remain pending until user decision; they do not imply acceptance.
8. Either Stop, GUI/core exit, active input disconnect, source close, lock/suspend, permission loss or fatal media error revokes control first and stops capture/audio/transport. Session/transport identity guards reject retired work; compatibility QImage presentation signals remain ordered on the shared worker/GUI queues. Reconnect never restarts capture. No persisted authorization.

## Implemented session API and boundaries

- Core starts `streaming::Service` on a dedicated Qt worker. It requires the verified Qt OpenSSL backend; Windows deployment uses `windeployqt --force-openssl` because the Schannel backend failed real mutual-TLS negotiation tests. Missing OpenSSL backend is an explicit error; no backend substitution. `Client::handshakeComplete` / `Server::adoptClient` publish a live input binding only after successful application admission at `PeerAuth`; disconnect/removal invalidates it synchronously. Service checks liveness on every incoming/outgoing authenticated message and every 100 ms for cleanup.
- Broker binds the accepted input socket's local address and input port + 1. Clients make one bounded sidecar probe per input generation. No input protocol version/opcode changes. Duplicate certificate identities are rejected. Channel handshake expires after 3 s; 64 pending/active channels maximum.
- `CoreProcess::streamingSession()` returns the GUI `streaming::SessionClient`. Connect `connectedChanged(bool)` and `received(QJsonObject)`; call `send(message(type, data))`. GUI reconnect attaches without media permission. `Capabilities` initially advertises empty sources/receive=false/control=false until real adapters report availability.
- `PrivateIpcServer`: one GUI attachment; Windows uses an overlapped native pipe listener with first-instance ownership, remote-client rejection and exact-logon/LocalSystem DACL. Native client handles request individual read/write rights and identification-only security quality of service before Qt socket adoption. PID/token/user/logon/nonzero-session identity is verified before parsing and on reads. Linux/macOS retain Qt user-access sockets with peer UID/PID/login-session checks. Existing world-access IPC never carries binding keys or grants.
- Windows delegation distinguishes the session-zero daemon from its active-session core. An already LocalSystem active-session core resolves the interactive user's token through WTS; its restricted DACL excludes client pipe-instance creation. The GUI validates a LocalSystem server in its own nonzero session; the server validates the exact interactive logon. Ordinary same-login desktop servers retain Qt generic-client compatibility. Login identity changes abort attachment; reconnect never restores media consent. No GUI elevation or change to established core elevation. Current-login real-pipe and own-token delegated-policy tests pass locally; actual elevated service execution and cross-token negative acceptance remain unapproved/unrun. Session zero remains rejected. Remote OS credential implementations remain uncompiled here.
- Wire frame: big-endian 32-bit length followed by canonical compact UTF-8 JSON; maximum 256 KiB including SDP. Noncanonical JSON (including duplicate keys), unknown envelope fields/type/version, invalid JSON, oversize frames and bounded-write overflow close transport. Envelope has exactly `v:1`, `type`, `data`. Authenticated network records add a strictly increasing integer sequence around the application envelope; replay/downgrade closes the channel. No exporter bytes leave core.
- `Capabilities` data: `sources:[screen|window|file]`, `receive:bool`, `audio:[off|system|application|file]`, `control:bool`. Arrays are bounded, unique enums. `Roster` supplies certificate-hash `id`, display `name`, connection `generation`, and verified capabilities plus authenticated `address`. Private IPC additionally emits `Identity:{id,address}` from the active core binding.
- `Offer` data: random lowercase 32-hex `session`, receiver 64-hex `to`, immutable 32-hex `source` generation, `kind`, `audio`, `preset:low|balanced|smooth`, `interactive:bool`. Optional `title` is at most 255 characters without control characters; sender sends only a sanitized file basename or source display title. Optional `playback:bool` explicitly permits receiver file commands and is false for other sources. Old offer fixtures without these optional fields remain valid. Broker derives origin and adds `from`/`generation` for receiver. One session per host; IDs cannot be reused in that broker lifetime (bounded 65,536 IDs).
- `Accept`, `Decline`, `Stop`, `Ready`, `Heartbeat`, `Pause`, `Resume`: exactly `{session,source}`. Only receiver accepts/declines; only sender changes playback state. Caller sends heartbeats each second after consent. Stop/disconnect/capability change/timeout revokes control notification before terminal `Stopped` and session removal. Decline/Stop produce no capture permission.
- States: `awaitingConsent` (30 s), `negotiating`, `awaitingAnswer`, `starting` (negotiation deadlines 10 s), `streaming`/`paused`; post-consent heartbeat timeout 3 s. `State` gives `{session,source,state,sender,receiver}`. `Stopped` gives `{session,source,reason}`; `Error` gives `{reason}`. Sender integration sends Ready on DTLS and wires source/OS loss to Stop; receiver first-decoded-frame Ready belongs to the viewer owner.
- `SdpOffer`/`SdpAnswer`: `{session,source,sdp,fingerprint}` after consent in sender/receiver order. Only bundled DTLS RTP audio/video SDP, RTCP mux, SHA-256 fingerprint allowed; audio m-lines are rejected when the accepted offer has audio off; repeated media fingerprints must all equal the announced value. Trickle candidates are separate. `IceCandidate`: `{session,source,candidate,mline}`; host UDP component 1 on that sender's authenticated input address and ports 24802–24831; optional bounded generation/network-id/network-cost/ufrag fields. No third-party/STUN/TURN/TCP candidates.
- `PlaybackState`: sender-only file timeline with exactly `{session,source,positionMs,durationMs,epoch,paused,seekable}`; integer nonnegative times with position <= duration <= 604800000 ms, integer epoch <= 2^53-1 that never decreases, boolean flags. Accepted in starting/streaming/paused. `PlaybackCommand`: receiver-only with exact `{session,source,action,positionMs,epoch}`; explicit offer playback permission, current file epoch, streaming/paused state, minimum 100 ms between commands. Actions pause/resume require position 0; seek requires seekable and integer 0 <= position < duration. Source/connection identity remains authenticated. A stale/rate-rejected command reports an error without ending a valid stream.
- Desktop grants now require the real core lease owner described below. File playback permission never enables desktop control; negotiation never injects input. DTLS-SRTP media remains in streaming-capture; native desktop input is owned by the core signaling worker.
- Automated proof covers actual OpenSSL input TLS exporters, separate Qt TLS 1.3 loopback channels, pinned identity/exporter/stale rejection, real private IPC, and two actual Service instances negotiating after a GUI Accept. The input TLS fixture uses OpenSSL memory BIO duplex transport; this is not a two-device or native-input E2E claim. Bundled audio/video SDP fixture exercises repeated fingerprints and libnice-style candidate extensions; actual media production is locally validated in item 06; packaged-runtime validation remains item 11.

## File playback, frame and input contracts

- Initial file acceptance target: WebM (VP8/VP9 + Opus/Vorbis), MP4/MOV (H.264 + AAC), Matroska with those codecs. Advertise only combinations verified against packaged decoders and actual fixtures; Windows SDK 1.28.7 decoded generated WebM VP8/Opus and VP9/Vorbis, H.264/AAC in MP4/MOV/Matroska, silent WebM and variable-frame-rate WebM. Other combinations and packaged/remote hosts remain unverified. Decode with a local-file-only GStreamer source/demux graph, not arbitrary URI/network playback. External subtitles/playlists/protocol handlers are outside scope.
- Generate owned fixtures from `videotestsrc`/`audiotestsrc` or existing FFmpeg CLI; no user-media permission needed for generated patterns. Include silent file, variable frame rate, truncated file and seek across keyframes. File audio uses decoded samples, never system loopback.
- Sender owns playback timeline. Pause freezes video and stops audio packets; Resume continues timestamps. Seek increments timeline epoch, flushes both endpoints and sends fresh keyframe; receiver discards prior-epoch data. End-of-file is visible and stops capture/control; replay is an explicit action.
- `VideoFrame`: owned buffer/texture reference + monotonic capture nanoseconds + source/timeline epoch + dimensions + pixel format/stride + colorimetry + crop/rotation/physical-to-logical transform. `AudioBlock`: samples + rate/channels/layout + monotonic PTS + duration + epoch. Never pass stack pointers across workers.
- Control is a core-owned expiring lease. Viewing-only injects zero events. File interactive mode sends playback commands only. Desktop grant requires local sender confirmation and persistent Revoke/Stop; sender local Escape revokes before any remote routing. Viewer focus loss/disconnect/revoke releases all injected held keys/buttons.
- While a media control lease exists, core suspends ordinary network input ownership and drops synthetic echoes. Local physical input wins over further control injection; core does not forward it under the old lease. Windows/macOS hooks can revoke synchronously; X11 drains native raw physical events before input verification and gates ordinary core dispatch. This does not specify when other local X applications receive events. Preserve per-recipient Windows-origin left-modifier mapping once and configurable 250 Hz motion coalescing. Windows exclusions block granting and injection. Native/cross-host coexistence acceptance remains required.
- Window input is confined to current verified window geometry; reject letterbox, stale source generation, source replacement and out-of-bounds coordinates. Screen coordinates use the frame's physical transform, not receiver pixels. Wayland control uses an explicitly consented RemoteDesktop portal/EIS session; ScreenCast permission is insufficient.

## Implemented capture API and validation boundaries (item 03)

### Codec, queues and diagnostics

- Software VP8 is the selected baseline. Low/Balanced/Smooth cap dimensions/FPS and target/maximum bitrate as specified above; no unverified hardware codec is selected. Frames downscale only to the accepted preset maximum and preserve original coordinate metadata. I420 BT.709 conversion precedes encoding. VP8 uses realtime deadline, zero lookahead, four threads, explicit CBR, rate-control buffers 100/50/50 ms and max-intra-bitrate 250. Encoder rate-control parameters do not prove end-to-end latency.
- Audio OFF creates no audio appsrc, encoder or RTP track and sends zero audio packets. Enabled tracks use 48-kHz stereo F32LE input, Opus 96 kbit/s, 20-ms packets and in-band FEC. Decoder removes only those priming/padding samples and preserves source PTS/epoch. Missing/invalid clipping metadata is terminal; both endpoints need this media build. IDs 2–6 retain existing video/source metadata and ID 1 remains TWCC.
- RTP jitter timestamps may repeat after a paused seek. `PacketMetadata` first binds video identity to its raw source buffer through encoding/packetization, then attaches authenticated identity/clipping bytes as untagged custom GstMeta to each received RTP buffer; depayloaders and codecs carry that ownership into the actual decoded audio/video buffer. Unmatched decoder output is discarded; no source timestamp is invented. Real fragmented VP8 decoding tests cover duplicate local PTS and middle-fragment loss with metadata checked against decoded color identity. GStreamer 1.28.7 [video decoder metadata copying](https://raw.githubusercontent.com/GStreamer/gstreamer/1.28.7/subprojects/gst-plugins-base/gst-libs/gst/video/gstvideodecoder.c) and [RTP metadata retention](https://raw.githubusercontent.com/GStreamer/gstreamer/1.28.7/subprojects/gst-plugins-good/gst/rtp/gstrtputils.c) define the copy contract.

Overflow/deadline stops the session. No encoded RTP is admitted before DTLS readiness; readiness forces a fresh keyframe. Startup requests repeat every 500 ms for the initial three seconds; an encoder pad probe counts actual upstream force-key-unit events.

Repeated sequence/epoch outputs are suppressed and static repeat telemetry is separate from source FPS. Raw appsrc: two latest video buffers; audio appsrc 60 ms/23,040 bytes. Sustained GCC estimate below 500 kbit/s for 3 s stops with insufficient bandwidth. These are explicit errors rather than silent source/preset/backend changes.

## Desktop control API and boundaries (item 09)

Source replacements require a new session. `Service::configureControl(exclusions, recipientName, motionHz)` receives existing configuration from the core app; constructing a service/fixture never initializes or rewrites user settings.
- Sender publishes `ControlGeometry` with `session/source/frame/epoch/geometry/x/y/width/height/valid` for each captured frame. Broker validates source identity, role, state and increasing frame. Geometry or epoch change revokes; native verification also rejects current window movement/resize/foreground mismatch before injection.
- `GrantControl{session,source,lease}`: source-local interactive non-file streaming session only. Core additionally requires idle native keys/buttons, ordinary input local, no other lease/viewer ownership, valid exact geometry and native target verification. Grant/revoke is delivered to both peers. Default viewing-only never injects.
- `ControlInput` always includes session/source/lease/sequence/frame/epoch/geometry. Duplicated ordinary downs, unmatched ups and replayed sequences are rejected.
- Viewer maps its letterboxed rectangle to the matching frame's physical source rectangle; outside input is ignored and releasing a dragged button outside revokes. ## Recovery and privacy boundaries (item 10)

- GUI operations retain the originating session ticket; input additionally retains its lease. Stale queued Stop/Accept/playback/volume/grant/revoke/focus/input cannot act on a later session.
